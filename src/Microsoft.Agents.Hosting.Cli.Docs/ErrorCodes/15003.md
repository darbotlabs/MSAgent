# 15003: Publication package could not be read

[All error codes](../ErrorCodes.md)

## What happened

The package selected for publication could not be read, either before transmission began or while the upload was in progress. An in-flight read failure leaves the remote upload outcome uncertain.

## Why this happens

The file may be missing, inaccessible, locked by another process, or still being changed by the process producing it. A directory or another unsuitable source cannot be sent as a regular package file.

## How to fix it

Confirm the path and ensure the intended artifact is a readable regular file. Wait for packaging to finish and resolve storage or access failures without broadening permissions unnecessarily. Keep the file unchanged while it is being read.

If the failure occurred before transmission began, retry the upload step with the correct file after fixing local access.

If the error reports `failureStage=request-body` and `failureReason=local-package-read-failed`, the read failed during an upload. Do not retry blindly: preserve the `clientRequestId` and intended agent, and check AMS package state or have the service owner inspect request correlation before deciding whether another upload is required. If a successful operation and Package Revision already exist for the intended artifact, use that verified result instead of uploading again.

If you cannot establish whether transmission began, treat the upload outcome as uncertain and perform the same remote-state check before retrying. Do not create or update a deployment merely to recover from a local file-read failure.

The current upload command is `msagent agent package upload`, available with `AmsFeatures`; it sends an existing artifact rather than building one.

## How to avoid it

Publish completed, stable artifacts from reliable storage, not files concurrently written by another process.
